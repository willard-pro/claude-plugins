# Ticket Audit Exec

Two-phase apply agent for recommendation checklists generated by `/ticket-audit`. Reads `{AUDIT_DIR}/recommendations/*.md`, applies findings in two separate invocations, archives completed files.

**Phases:**
- **Run 1 — Needs-info**: Delegates each pending needs-info item to `/ticket-critique {ID}`, then exits. Human resolves flagged tickets before run 2.
- **Run 2 — Structural**: Posts comments on affected tickets for pending structural + drift items, then archives.

**Flags:**
- `--file <path>` — target a specific recommendation file
- `--dry-run` — print planned actions without mutations or file changes

**Key invariants:**
- Never mutates Linear directly — needs-info goes through ticket-critique; structural posts comments only
- Hard exit after run 1 — structural phase cannot run in the same invocation
- Write-ahead `[>]` for crash recovery — prevents double-apply on resume
- Dedup guard (`audit-comment-guard.sh`) before every delegation/post

---

## Step 0: Parse flags and source libraries

Parse all arguments:
- `--file <path>` → RESOLVED_FILE=$path (skip selection sort)
- `--dry-run` → DRY_RUN=true

```bash
DRY_RUN=false
RESOLVED_FILE=""

while [ $# -gt 0 ]; do
  case "$1" in
    --file) RESOLVED_FILE="$2"; shift 2 ;;
    --dry-run) DRY_RUN=true; shift ;;
    *) echo "Unknown flag: $1"; exit 1 ;;
  esac
done

# Source libraries
PLUGIN_LIB="$(cd "$(dirname "${BASH_SOURCE[0]}")" 2>/dev/null && cd ../../lib && pwd || echo "$HOME/.claude/skills/lib")"
source "$PLUGIN_LIB/config.sh"
source "$PLUGIN_LIB/ticket-audit-exec.sh"

echo "DRY_RUN=$DRY_RUN"
echo "RESOLVED_FILE=$RESOLVED_FILE"
echo "AUDIT_DIR=$AUDIT_DIR"
```

Note: `ticket-audit-exec.sh` exports `resolve_file`, `parse_checklist`, `write_ahead_mark`, `mark_item_done`, `mark_item_failed`, `advance_phase`, `archive_checklist`, `has_pending_items`, and `get_item_state`.

---

## Step 1: File resolution

Resolve the target recommendation file.

```bash
eval "$(resolve_file "$RESOLVED_FILE")"
echo "TARGET_FILE=$TARGET_FILE"
```

If the command exits non-zero, display the error and stop.

---

## Step 2: Parse checklist

Parse the recommendation file to extract phase, items, and counts.

```bash
CHECKLIST=$(parse_checklist "$TARGET_FILE")
echo "$CHECKLIST" | jq '{phase, source_id, pending_needs_info, pending_structural, total_needs_info, total_structural}'
```

Store the full JSON for item iteration:

```bash
CURRENT_PHASE=$(echo "$CHECKLIST" | jq -r '.phase')
SOURCE_ID=$(echo "$CHECKLIST" | jq -r '.source_id')
PENDING_NEEDS_INFO=$(echo "$CHECKLIST" | jq -r '.pending_needs_info')
PENDING_STRUCTURAL=$(echo "$CHECKLIST" | jq -r '.pending_structural')

echo "Phase: $CURRENT_PHASE"
echo "Source ID: $SOURCE_ID"
echo "Pending needs-info items: $PENDING_NEEDS_INFO"
echo "Pending structural items: $PENDING_STRUCTURAL"
```

---

## Step 3: Dry-run fast path

If `--dry-run` is set, print planned actions and exit without mutations.

**If DRY_RUN is true:**

Read the phase from Step 2's output. For each section:

1. Print the resolved file path, current Phase, and source ID.
2. For each pending needs-info item (`state` = `pending` or `resumed`): print ticket ID, detail, and "→ delegate to /ticket-critique {ID}"
3. For each pending structural item: print ticket ID, detail, and "→ post comment to {ID}"
4. If `needs-info` phase with 0 pending → print "→ would fast-path to Phase: needs-info-done"
5. If `needs-info-done` phase with 0 pending structural → print "→ would proceed directly to archive"
6. If `structural-done` phase → print "→ would archive file"
7. End with "=== END DRY RUN (no mutations performed) ===" and exit 0.

**Do not make any Linear API calls. Do not modify any files.**

---

## Step 4: Needs-info phase (run 1)

### 4a: Phase skip

If CURRENT_PHASE is `needs-info-done` or `structural-done`:
- Print "Needs-info phase already complete (Phase: {CURRENT_PHASE})"
- Skip to Step 5.

### 4b: Empty section fast-path

If PENDING_NEEDS_INFO is 0:
```bash
advance_phase "$TARGET_FILE" "needs-info-done"
```
Print run 1 summary (0 delegated, 0 failed) and exit 0.

### 4c: Process each needs-info item

For each item in `needs_info_items` where state is `pending` or `resumed`:

Extract items needing processing (includes `detail_clean` and `all_ticket_ids`):
```bash
echo "$CHECKLIST" | jq -r '.needs_info_items[] | select(.state == "pending" or .state == "resumed") | "\(.ticket_id)|||\(.detail)|||\(.detail_clean)|||\(.all_ticket_ids)"'
```

For each pending item (iterate through the IDs):

1. **Write-ahead**: Mark the item `[>]` in the file:
   ```bash
   write_ahead_mark "$TARGET_FILE" "{TICKET_ID}"
   ```

2. **Dedup guard**: Call the guard script:
   ```bash
   GUARD_SOURCE="${SOURCE_ID}:{TICKET_ID}:needs-info"
   if bash "$PLUGIN_LIB/audit-comment-guard.sh" "{TICKET_ID}" "$GUARD_SOURCE"; then
     echo "Dedup: existing audit comment found for {TICKET_ID} — skipping"
     mark_item_done "$TARGET_FILE" "{TICKET_ID}"
     continue to next item
   fi
   ```

3. **Delegate to ticket-critique**: Call `/ticket-critique {TICKET_ID} --from-audit --source-marker "{SOURCE_ID}:{TICKET_ID}:needs-info"`

   Pass the audit finding detail as context so ticket-critique knows what the audit found:
   ```
   /ticket-critique {TICKET_ID} --from-audit \
     --source-marker "{SOURCE_ID}:{TICKET_ID}:needs-info"
   ```
   The finding detail (`detail_clean` from the checklist JSON) is available for ticket-critique to reference.

   On success (exit 0):
   ```bash
   mark_item_done "$TARGET_FILE" "{TICKET_ID}"
   ```
   Increment delegated count.

   On failure (exit non-zero):
   ```bash
   mark_item_failed "$TARGET_FILE" "{TICKET_ID}"
   ```
   Record "{TICKET_ID}: ticket-critique failed" in the failure list.

   **Dedup coverage:** ticket-critique with `--from-audit` includes `Source: {source-marker}` in its comment footer. On crash/resume, the guard finds this marker and skips re-delegation.

### 4d: Advance phase and print summary

After all needs-info items processed:

```bash
advance_phase "$TARGET_FILE" "needs-info-done"
```

Print run 1 summary:
- Items delegated: (count)
- Failed: (count) with list of `[!]` ticket IDs
- Instruction: "Resolve needs-info tickets, then re-run ticket-audit-exec for structural phase."

Exit 0. **Do not proceed to Step 5 in the same invocation.**

---

## Step 5: Structural phase (run 2)

This step only executes if CURRENT_PHASE is `needs-info-done` (Step 4 was skipped due to phase gate in 4a).

### 5a: Phase gate

If CURRENT_PHASE is `needs-info` (run 1 not complete):
- Print "Needs-info phase not yet complete. Resolve flagged tickets and re-run ticket-audit-exec."
- Exit 0.

### 5b: Empty section fast-path

If PENDING_STRUCTURAL is 0:
- Print "No pending structural items — proceeding to archive."
- Skip to Step 6.

### 5c: Process each structural item

For each item in `structural_items` where state is `pending` or `resumed`:

Extract items needing processing (includes `detail_clean` and `all_ticket_ids` for multi-ticket handling):
```bash
echo "$CHECKLIST" | jq -r '.structural_items[] | select(.state == "pending" or .state == "resumed") | "\(.ticket_id)|||\(.detail)|||\(.detail_clean)|||\(.all_ticket_ids)"'
```

For each pending item (iterate through the IDs):

1. **Write-ahead**: Mark the item `[>]` in the file:
   ```bash
   write_ahead_mark "$TARGET_FILE" "{TICKET_ID}"
   ```

2. **Dedup guard**: Call the guard script:
   ```bash
   GUARD_SOURCE="${SOURCE_ID}:{TICKET_ID}:structural"
   if bash "$PLUGIN_LIB/audit-comment-guard.sh" "{TICKET_ID}" "$GUARD_SOURCE"; then
     echo "Dedup: existing audit comment found for {TICKET_ID} — skipping"
     mark_item_done "$TARGET_FILE" "{TICKET_ID}"
     continue to next item
   fi
   ```

3. **Compose and post comment**: Extract the finding type from the detail (first colon-delimited segment, e.g., "merge candidate", "split candidate", "duplicate", "drift", "goal misalignment"). Use `detail_clean` (stripped of the finding type prefix) to avoid redundancy.

   **Multi-ticket findings** (merge candidates, duplicates): When `all_ticket_ids` contains more than one ticket ID, post the comment on EVERY affected ticket. For example, if `all_ticket_ids` is "WIL-78 WIL-79", post on both WIL-78 AND WIL-79.

   Compose the comment body:
   ```
   Audit recommendation: {finding_type}
   {detail_clean — the finding description without the redundant type prefix}
   Source: {SOURCE_ID}:{TICKET_ID}:structural
   ```

   Post via the MCP Linear comment tool. Post on the primary ticket AND on each sibling ticket from `all_ticket_ids`. Use a separate dedup guard call for each sibling.

   On success (all posts):
   ```bash
   mark_item_done "$TARGET_FILE" "{TICKET_ID}"
   ```
   Increment comment count by the number of tickets commented on.

   On failure (any post fails):
   ```bash
   mark_item_failed "$TARGET_FILE" "{TICKET_ID}"
   ```
   Record "{TICKET_ID}: comment post failed on {sibling} — {error}" in the failure list.

### 5d: Advance phase to structural-done

After all structural items processed:

```bash
advance_phase "$TARGET_FILE" "structural-done"
```

---

## Step 6: Archive

After structural phase completes, or if both phases were already done:

```bash
if has_pending_items "$TARGET_FILE"; then
  echo "Some items remain pending — skipping archive"
else
  eval "$(archive_checklist "$TARGET_FILE")"
  echo "Archived to: $ARCHIVE_PATH"
fi
```

If archive was already done (Phase is `structural-done` and no pending items), the file may already be in the archive directory. Check both locations:
```bash
ARCHIVE_FILE="${AUDIT_DIR}/archive/$(basename "$TARGET_FILE")"
if [ -f "$ARCHIVE_FILE" ]; then
  echo "Already archived: $ARCHIVE_FILE"
fi
```

---

## Step 7: Print summary

### Run 1 summary (after Step 4)
Already printed in Step 4d with:
- Items delegated to ticket-critique
- `[!]` failures with ticket IDs
- "Resolve needs-info tickets, then re-run ticket-audit-exec for structural phase."

### Run 2 summary (after Step 5+6)

Print:
- Comments posted: (count)
- Failed: (count) with list of `[!]` ticket IDs and error reasons
- Archive path (if archived)
- If any `[!]` items remain: "Investigate failed items manually — see checklist for details."

## Item state reference

| State | Markdown | Meaning | Action on re-invocation |
|---|---|---|---|
| Pending | `- [ ]` | Never attempted | Process normally |
| In-progress | `- [>]` | Prior run crashed during processing | Re-process from start (dedup guard prevents double-apply) |
| Complete | `- [x]` | Applied successfully | Skip |
| Failed | `- [!]` | Error during application | Skip (reported in summary; human investigates) |

## Phase state machine

```
needs-info ──(run 1)──▶ needs-info-done ──(run 2)──▶ structural-done ──▶ archive/
     ▲                        │                         │
     │                        │                         │
     └── unrecognized         └── run 1 incomplete      └── all items [x]/[!]
        (treat as needs-info)    (block structural,        (move to archive/)
                                 exit with message)
```
