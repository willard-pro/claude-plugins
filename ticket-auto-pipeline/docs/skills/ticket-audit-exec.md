# ticket-audit-exec

> Two-phase apply agent for ticket-audit recommendation checklists. Run 1 delegates needs-info items to ticket-critique; run 2 posts structural comments on affected tickets. Use /ticket-audit first. Flags: --file <path>, --dry-run.

## What it does

Consumes recommendation checklists generated by `/ticket-audit` and applies findings in two separate invocations. Run 1 delegates each pending needs-info item to `/ticket-critique` (which posts Linear comments and adds the `needs-info` label), then exits — structural phase cannot run in the same invocation. Run 2 posts structural comments (merge candidates, split suggestions, drift, goal misalignment) on affected tickets and archives the completed checklist. Uses write-ahead marks for crash recovery and dedup guards to prevent double-application on resume.

## Trigger

**Slash command:** `/ticket-audit-exec [--file <path>] [--dry-run]`

**Natural language:** apply audit findings, execute audit recommendations, run audit checklist

## Inputs

| Input | Source | Required |
|-------|--------|----------|
| Recommendation file | --file flag or auto-selection | Yes |
| LINEAR_API_KEY | Env or settings.local.json | Yes |
| ticket-critique skill | Plugin skills | Yes (for needs-info delegation) |
| --dry-run flag | CLI | No (preview without mutations) |

## Outputs / Artifacts

| Artifact | Location | Description |
|----------|----------|-------------|
| Updated checklist | Recommendation file | Items marked [x] (done), [>] (in-progress), or [!] (failed) |
| Phase transitions | Recommendation file header | needs-info → needs-info-done → structural-done |
| Archived checklist | {AUDIT_DIR}/archive/ | Completed file moved to archive |
| Linear comments | Affected tickets | Structural findings posted via MCP |
| needs-info labels | Flagged tickets | Applied by ticket-critique delegation |

## How it works

```mermaid
flowchart TD
    A[Start: /ticket-audit-exec] --> B[Parse flags + source libs]
    B --> C[Resolve file]
    C --> D[Parse checklist JSON]
    D --> E{--dry-run?}
    E -->|Yes| F[Print planned actions]
    F --> EXIT0[Exit 0]
    E -->|No| G{Phase?}
    G -->|needs-info| H[Process needs-info items]
    H --> I[Write-ahead mark [>]]
    I --> J[Dedup guard]
    J --> K[Delegate to /ticket-critique]
    K --> L[Mark [x] or [!]]
    L --> M[Advance to needs-info-done]
    M --> EXIT1[Exit 0 — re-run for structural]
    G -->|needs-info-done| N[Process structural items]
    N --> O[Write-ahead mark [>]]
    O --> P[Dedup guard]
    P --> Q[Post comment on ticket + siblings]
    Q --> R[Mark [x] or [!]]
    R --> S[Advance to structural-done]
    S --> T[Archive file]
    T --> EXIT2[Print summary]
    G -->|structural-done| T
```
